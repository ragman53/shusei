# T02: Implement Word Tap Detection

**Slice:** S03 — PDF Reflow Reader
**Milestone:** M002-dbrk2n

## Description

Implement word tap interaction: when user taps a word in the PDF reader, extract the word text + surrounding sentence context, save to `words` table with `definition: None` (placeholder per D007), and show "Word saved!" toast notification. This delivers R003 (word + example sentence collection).

## Steps

1. Add onclick handler to word spans generated by `render_markdown_to_html()` from T01
2. Create `handle_word_tap(word: String, page: BookPage)` function that:
   - Calls `WordExtractor::extract_sentence()` with page text to get context
   - Calls `db.create_word()` with: `word`, `definition: None`, `context_text: Some(sentence)`, `source_book_id: Some(book_id)`, `source_page: Some(page_number)`, `ai_generated: false`
   - Shows toast notification "Word saved!"
   - Handles duplicate words (check if word exists; if so, skip or show "Already saved")
3. Add visual feedback: highlight tapped word briefly (CSS animation or color change)
4. Add "Definition coming soon" placeholder state for word detail (prepare for S04)
5. Test with PDF containing 10+ words; verify all save correctly

## Must-Haves

- [ ] Word tap saves to `words` table with correct schema
- [ ] Sentence context extracted using `WordExtractor::extract_sentence()`
- [ ] Toast notification appears on successful save
- [ ] Duplicate word handling (skip or update, no crash)
- [ ] Visual feedback on tap (highlight or animation)
- [ ] `definition: None` and `ai_generated: false` per D007

## Verification

- `cargo test --lib reader::test_word_tap` — Word saved with sentence context
- `cargo test --lib vocab::test_extract_sentence` — Sentence extraction works for English text
- Manual test: Tap 3 words in reader → check `words` table via `sqlite3 shusei.db "SELECT * FROM words;"` → verify word, sentence, book_id, page_number present

## Observability Impact

- **Signals added/changed:**
  - Word tap event logged with word text, book_id, page_number
  - Duplicate word detection logged (info level)
  - Save errors logged with full error context
- **How a future agent inspects this:**
  - `sqlite3 shusei.db "SELECT word, context_text, source_book_id FROM words;"` — verify saved words
  - `adb logcat | grep -i "word saved"` — tap events in logs
  - Browser console for error messages on tap failures
- **Failure state exposed:**
  - Toast with error message if save fails
  - Console log with database error details
  - Word not highlighted if save unsuccessful
